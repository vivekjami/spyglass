# Benchmark

**Status:** methodology only. **No results exist yet** — every number below is
`[MEASURE AFTER IMPLEMENTATION]`. Result tables are generated by
`bench/report.py` from committed run files and are **never hand-edited**.

## The controlled comparison

Two conditions, identical in **model, harness, incident, information access, and
action path**, differing only in the evidence interface:

- **BASELINE** — raw telemetry tools (`tail_logs`, `grep_logs`, `get_metric`,
  `list_services`, `deploy_events`) → gated `rollback`.
- **SPYGLASS** — the evidence plane (bounded, ranked, novelty/changepoint-aware
  tools + bundles) → gated `rollback`.
- **ABLATION A1** — Spyglass with `novel_templates` disabled, isolating the
  headline tool's contribution. Implemented as a `disable_tools` entry, not a
  code change.

## Conditions as built

Each condition is a TrueForge agent manifest in `bench/conditions/`, registered
by name with `just tf-setup`. `bench/conditions/README.md` carries the fairness
checklist and the information-access mapping between raw and shaped tools.

| Condition | Agent | Read tools | Action path | Status |
|---|---|---|---|---|
| BASELINE | `spyglass-baseline` | `spyglass-rawtools`: `list_services`, `tail_logs`, `grep_logs`, `get_metric`, `deploy_events` | `spyglass-deployer`: `rollback` (approval-required), `current_versions` | built (Phase 2) |
| SPYGLASS | `spyglass` | the evidence plane (Phase 3+) | the same deployer server, same gate | Phase 3 |
| ABLATION A1 | `spyglass-no-novelty` | Spyglass with `disable_tools: ["novel_templates"]` | same | Phase 10 |

One investigation = `scripts/investigate.py --condition <c> --scenario <s>`:
it opens a session on the named agent, posts the alert, drives the approval
gate per policy (`ask` for filmed runs, `allow`/`deny` unattended), and writes
`bench/results/<s>-<c>-<run>.json` with the metrics below plus the full event
trace, so every number is traceable to what happened.

## Pinned harness settings (ADR-016)

Every condition file states these explicitly rather than inheriting defaults,
because TrueForge's defaults would otherwise shape the baseline's tool output
and contaminate the control group:

```json
"config": {
  "iteration_limit": <pinned>,
  "context_management": {
    "compaction":          {"enabled": false},
    "large_tool_response": {"enabled": false}
  }
}
```

Plus, on every MCP server entry, `"preload": true` — deferred tool loading
otherwise adds harness-side `list_tools`/`get_tool_info` calls to the tool-call
metric, unevenly across conditions.

Rationale and reversal conditions: [ADR-016](adr/ADR-016-harness-context-management-pinning.md).

## Metrics

Investigation success · root-cause accuracy (top-1) · evidence precision ·
evidence recall · tool calls · input/output/total tokens · estimated cost
(provider price sheet committed with results) · investigation latency (RCA, and
separately verified-close including human approval latency) · time to first
useful hypothesis · false hypotheses · verification success.

Engine-side, per condition: tool-call latency P50/P95/P99, bundle reduction
ratio, bytes served to context.

**How tokens are counted.** A turn's `state.output.usage` is the usage of its
*final* model call only. Metrics 6–8 are therefore computed by summing
`usage` over every `model.message` event in the turn's event stream, across
the main thread and every sub-agent thread (`scripts/tf.py::usage_total`).
Measured in Phase 0: a turn with one trivial sub-agent was 2745/197 tokens
by the sum and 1340/30 by the turn-level field.

## Statistical honesty

n=3 repeats per cell is a hackathon budget, not a study. Therefore:

- Report per-run values and ranges, not just means.
- **Claim no statistical significance** — at n=3 none is justified.
- Treat model nondeterminism as irreducible noise; let disagreement across
  repeats stay visible.
- State the bias plainly: scenario authorship and system authorship are the same
  person. Mitigated — not eliminated — by pinned seeds, ground truth committed
  *before* benchmark runs, and raw run files in the repo.
- Cherry-picking is structurally prevented: **every** run is committed to
  `bench/results/`, including failures.
