## The controlled comparison

Two conditions, identical in **model, harness, incident, information access, and
action path**, differing only in the evidence interface:

- **BASELINE** — raw telemetry tools (`tail_logs`, `grep_logs`, `get_metric`,
  `list_services`, `deploy_events`) → gated `rollback`.
- **SPYGLASS** — the evidence plane (bounded, ranked, novelty/changepoint-aware
  tools + bundles) → gated `rollback`.
- **ABLATION A1** — Spyglass with novelty disabled, isolating the headline
  tool's contribution. The spec said "a `disable_tools` entry"; as built it is
  a second instance of the same engine binary started with `--ablation
  no-novelty` *plus* that entry, because the bundle embeds the novelty miner's
  output (Phase 10 F5).

## Conditions as built

Each condition is a TrueForge agent manifest in `bench/conditions/`, registered
by name with `just tf-setup`. `bench/conditions/README.md` carries the fairness
checklist and the information-access mapping between raw and shaped tools.

| Condition | Agent | Read tools | Action path | Status |
|---|---|---|---|---|
| BASELINE | `spyglass-baseline` | `spyglass-rawtools`: `list_services`, `tail_logs`, `grep_logs`, `get_metric`, `deploy_events`, `http_request` (one request, like `curl` — the raw counterpart of the replay, Phase 8) | `spyglass-deployer`: `rollback` (approval-required), `current_versions` | built (Phase 2; `http_request` Phase 8) |
| SPYGLASS | `spyglass` | the evidence plane: `build_evidence_bundle` (the starter), `novel_templates`, `detect_changepoints`, `error_delta`, `deploy_events`, `freshness_watermark`, `get_evidence`, `search_logs`, `service_topology`, and the causal check `get_exemplar_request` → `replay_exemplar` | the same deployer server, same gate | built (Phases 3–8) |
| ABLATION A1 | `spyglass-no-novelty` | a **second instance of the same engine** (`spyglass-engine-ablation`, :8794, `--ablation no-novelty`): `novel_templates` refuses, the bundle carries no template candidates, `w_n = 0`; templates reachable only through `search_logs`; plus `disable_tools: ["novel_templates"]` in the condition file | same | built (Phase 10) — the spec's "one line in the condition file" was not enough: the bundle embeds the novelty miner's output |

One investigation = `scripts/investigate.py --condition <c> --scenario <s>`:
it opens a session on the named agent, posts the alert, drives the approval
gate per policy (`ask` for filmed runs, `allow`/`deny` unattended), and writes
`bench/results/<s>-<c>-<run>.json` with the metrics below plus the full event
trace, so every number is traceable to what happened.

## Pinned harness settings (ADR-016)

Every condition file states these explicitly rather than inheriting defaults,
because TrueForge's defaults would otherwise shape the baseline's tool output
and contaminate the control group:

```json
"config": {
  "iteration_limit": <pinned>,
  "context_management": {
    "compaction":          {"enabled": false},
    "large_tool_response": {"enabled": false}
  }
}
```

Plus, on every MCP server entry, `"preload": true` — deferred tool loading
otherwise adds harness-side `list_tools`/`get_tool_info` calls to the tool-call
metric, unevenly across conditions.

Rationale and reversal conditions: [ADR-016](adr/ADR-016-harness-context-management-pinning.md).

## Metrics — as scored

| # | Metric | As built (`bench/report.py`) |
|---|---|---|
| 1 | Investigation success | terminal state equals the scenario's `correct_action`: for rollback scenarios, exactly one rollback of the right service to the right version executed; for S3/S6, nothing executed *and* the closing `verdict` block says the right report / refusal |
| 2 | Root-cause accuracy | the verdict's `culprit_service` and `culprit_change` are both in the ground truth's accepted lists (`none` is a value); no verdict block → not correct |
| 3 | Evidence precision | relevant cited evidence ids ÷ cited ids — each cited id resolved to the item the engine returned (the trace keeps every tool response) and matched against the ground truth's `match` maps; a cited decoy counts against it. **Spyglass conditions only**: the baseline has no evidence ids — its claims are not re-checkable, which is a finding |
| 4 | Evidence recall | `key: true` expected-evidence entries with at least one relevant citation ÷ key entries |
| 5 | Tool calls | the agent's own tool calls across every thread (`preload: true` keeps harness tool-listing calls out) |
| 6–8 | Input / output / total tokens | summed over every model call in every thread (`tf.usage_total`); input reported with its cache-read share and as *uncached* input |
| 9 | Estimated cost | tokens × `bench/price-sheet.json`; the harness catalog exposes no prices, so the column reads `n/a` until the sheet is filled from the provider's published list — tokens stand as the proxy |
| 10 | Investigation latency | alert → final RCA (wall, includes model latency); separately alert → the engine's `verified_recovery` entry where one exists |
| 11 | Time to first useful hypothesis | alert → first assistant message containing every term of any `first_hypothesis_terms` group |
| 12 | False hypotheses | proxied by *decoy mentions*: interim assistant messages naming a `decoy_terms` entry — a count, not a judgment |
| 13 | Verification success | rollback scenarios: the engine's `verified_recovery` (Spyglass); the agent's own post-action metric re-check plus the runner's post-run edge 5xx under `pre_fault_max` (baseline) |

Engine-side, per run: tool-call latency (every ledger entry), bundle
reduction ratio, bytes served to context (`tool_response_bytes`).

**The gate in the matrix.** Unattended runs auto-approve, so a wrong
proposal executes and is scored as a wrong action — the conservative
reading. The demo's gate is real (`--approval ask`).

**How tokens are counted.** A turn's `state.output.usage` is the usage of its
*final* model call only. Metrics 6–8 are therefore computed by summing
`usage` over every `model.message` event in the turn's event stream, across
the main thread and every sub-agent thread (`scripts/tf.py::usage_total`).
Measured in Phase 0: a turn with one trivial sub-agent was 2745/197 tokens
by the sum and 1340/30 by the turn-level field.

## Preliminary single runs (n=1 — not results)

Recorded here so the numbers exist before the treatment does and cannot be
tuned toward afterwards. **n=1–2, one model, one scenario; no claim rests on
this table.** On S1 the treatment matches the baseline on correctness, cuts
tool bytes and peak context, cites every claim; Phase 3's engine did **not**

## Statistical honesty

n=3 repeats per cell is a hackathon budget, not a study. Therefore:

- Report per-run values and ranges, not just means.
- **Claim no statistical significance** — at n=3 none is justified.
- Treat model nondeterminism as irreducible noise; let disagreement across
  repeats stay visible.
- State the bias plainly: scenario authorship and system authorship are the same
  person. Mitigated — not eliminated — by pinned seeds, ground truth committed
  *before* benchmark runs, and raw run files in the repo.
- Cherry-picking is structurally prevented: **every** run is committed to
  `bench/results/`, including failures.
